## [Unreleased]

### Added
- The panel in real browsers (issue 53, PR 11c-2a, ADR-0018): `make panel-check` runs `tests/browser` with Playwright in Chromium, Firefox and WebKit (`PANEL_BROWSERS=chromium` for one); not part of `make check`. Each test starts its own gateway in-process on `127.0.0.1` (free port, throwaway tokens, no `.env`, providers that fail if used, loopback only) and a new browser context whose route aborts and records anything outside it. Checks: no CSP violation and a clean console on the login and panel placeholders, no inline code in the live DOM, login and logout with `fetch` from the page (through the door with the browser's own `Origin` and `Sec-Fetch-Site`), the `antifaz_session` cookie attributes, empty `document.cookie` and storage, 401 and 429, nothing left after logout, and axe-core (bundled, no CDN) with 0 violations in light and dark at 1280 and 390 px in a separate `bypass_csp` context. Two canaries prove the CSP detector and the route block work in each browser. Failures leave only a screenshot and a redacted log, never traces, videos or HAR. New `panel` dependency group (Playwright 1.63.0, axe-playwright-python 0.1.8), locked in `uv.lock`, never installed by `uv sync` and never in the image (unit tests and `make e2e`). New CI job "Panel in a real browser (Chromium)" (headless shell only, no secrets, uploads only failure screenshots and logs). Playwright's WebKit for Windows stores no `SameSite` (it reports `None` for the `SameSite=Strict` cookie); the test checks the `Set-Cookie` header in every browser.
- The e2e tests can never reach a real provider (no internet egress). The gateway and the fake provider run only on a Compose network with `internal: true` and `com.docker.network.bridge.inhibit_ipv4` (no address for the Docker host either), with a fixed subnet per stack (`tests/e2e/docker-compose.no-egress.yml`, also used by the stack started with the `.env` written by `init`). Since Docker does not publish ports from an internal network, a standard-library relay in the Antifaz image (`tests/e2e/relay.py`: read-only, no capabilities, no new privileges, `cpus: 0.5`) is the only door from the host: it publishes on `127.0.0.1` only and copies bytes to fixed IPs inside the internal subnet (no name lookups, never where a client asks), with a 5 s connect timeout, at most 64 connections and an idle timeout. A canary e2e test tries a TCP connection (no byte sent) from inside the gateway and the fake provider, in both stacks, to the providers by name and by the IPs resolved on the host, to `1.1.1.1`, `8.8.8.8`, `2606:4700:4700::1111` and to the gateways of the Docker networks on ports 80, 443, 3128 and 8080, and judges each result against an allow-list (unreachable; DNS failure only for names), printing every destination with its errno; before this change the providers and the public IPs connected and the host answered. A run-time check confirms the internal network, that it gives the host no address and that the containers are only on it, and the gateway's effective settings are read as booleans (both base URLs plain http to `fake-upstream:9000`). The e2e session refuses to start unless both provider base URLs in the throwaway env file are exactly plain http to `fake-upstream:9000` (visible ASCII only, no user part, query or fragment). Every `docker run` uses `--network none`: a fail-closed static unit test (allow-listed options only, `--network none` as the only network, `create` and `container run` included; `compose ... run`, `shell=True` and docker command lines in strings refused) and the same check at run time in the e2e `docker()` helper. The CI prints the Docker versions before the e2e tests.
- Panel static files and templates (issue 53, PR 11c-1, ADR-0018 and its note of 2026-10-16). `web/assets.py` (standard library) reads a fixed list of files once at startup, publishes each as `name.<12 hex of its SHA-256>.ext` under `/panel/static/`, rewrites the `url()` references inside the CSS to the hashed names and keeps everything in memory; `GET /panel/static/{name}` (`async def`) answers from that read-only dict by exact name, never from the disk. `web/templating.py` renders the pages from Jinja2 templates (`base.html`, `login.html` and `panel.html`, placeholders until 11c-2) with autoescape and `StrictUndefined`, compiled once at startup from memory and only with server values (the manifest's fixed URLs and the session's CSRF token); never `Jinja2Templates` or `request.url_for`. `pages.py` keeps only the fixed «Solo HTTPS» page. `panel.css` is the approved prototype's CSS without its prototype-only parts, and the grain background is `grain.svg` instead of a `data:` URI. Jinja2 (BSD-3-Clause) and MarkupSafe are direct dependencies now (they leave `RECORDED_EXTRA`). A test builds the wheel and checks it ships every static file, the OFL text next to each font and the templates; under `make e2e`, the image serves a static file and holds the OFL texts.
- Panel door, part 2: getting out (issue 53, PR 11b-2b, ADR-0018). `POST /panel/logout` (`async def`, never awaits) closes the session on the server and answers `{"ok": true}` with exactly one `Set-Cookie`, the expired cookie of the request's scheme (same name and attributes, empty value, `Max-Age=0`), and `Clear-Site-Data: "cache"` (never `"cookies"`, which on localhost would wipe every app's cookies). Without a live session it is 401 and no cookie is touched. `sessions.watch(store, fingerprint, cut)` tells one session's subscriber, once, why it closed: the hook for the live view's SSE (11e).
- Panel door, part 1: getting in (issue 53, PR 11b-2a, ADR-0018 and its addendum of 2026-10-13). `GateMiddleware` sends every `/panel` or `/panel/...` path (decoded `scope["path"]`, before the public paths and the key) to the panel's door and never to the API key rules; `/PANEL`, `//panel` and `/panelx` stay on the gateway side. Without `ANTIFAZ_ADMIN_TOKEN` every panel path is a fixed JSON 404 and `antifaz.web` is not imported. With it, `create_app` hands the door and routes only a `PanelState` (the token's SHA-256, the trusted proxies, an in-memory session store and the login limiter). Routes, all `async def` and outside the OpenAPI schema: `GET /panel/login` (placeholder page until 11c), `POST /panel/login` (JSON `{"token": ...}`) and `GET /panel` (placeholder with the session's CSRF token in a `<meta>`; without a session, 303 to `/panel/login`). New standard-library modules `cookies.py`, `csrf.py`, `headers.py` and `pages.py`, plus `door.py` and `routes.py`. `AppError` gains fixed `headers` (used for `Retry-After`), and the panel errors. `AppError`, `error_body()`, `error_response()` and the panel errors live in a neutral `antifaz/http_errors.py` and `route_path()` in a standard-library `antifaz/routing.py`, so no `antifaz.web` module loads `antifaz.config`, even indirectly; a test imports each web module in a fresh interpreter and walks its project imports statically (with negative cases). No logout yet (11b-2b).
- Panel door, configuration and pure pieces (issue 53, PR 11b-1, ADR-0018); no route is added and the gateway behaves as before. New variables `ANTIFAZ_ADMIN_TOKEN` (the panel exists only when it is set) and `ANTIFAZ_TRUSTED_PROXIES` (IPs or CIDR ranges of a reverse proxy, empty by default) in the settings, `.env.example` and `init`'s template. `antifaz init` always generates the admin token like the key (`secrets.token_hex(32)`, drawn again if equal to the key), shows it under the same rule (terminal or `--show-key`) and says how to turn the panel off (delete the line and restart). `antifaz doctor` notes `panel: on/off` and `trusted proxies: N` (a count, never the addresses). Standard-library modules under `antifaz.web` for the next PR: `forwarded.py` (client IP walking `X-Forwarded-For` right to left and only from trusted proxies, `X-Forwarded-Proto` only as one exact value from a trusted proxy, `localhost` decided by the `Host`), `sessions.py` (`SessionStore` and an in-memory store that keeps only the SHA-256 of the session id, 8 h absolute and 30 min idle, close notifications, the oldest session evicted when full so a login is never refused) and `login_limit.py` (5 failures per IP in any 60 s, `Retry-After` rounded up, no global limit, a bounded table that never blocks a new IP). Install guides (English and Spanish) and docs/TECNICO.md updated; the `antifaz.web` docstring now says Jinja2 + native JavaScript (no HTMX).
- `antifaz init` (issue 41, ADR-0017 proposed): writes a `.env` that passes the startup check, without network. `ANTIFAZ_API_KEY` is made locally (`secrets.token_hex(32)`) and shown once, only on a terminal or with `--show-key`. Provider keys never come from the command line: hidden input (`getpass`), or with `--non-interactive` the environment variable named by `--openai-key-env`/`--anthropic-key-env` or stdin (`--openai-key-stdin`/`--anthropic-key-stdin`, one at most); spaces, quotes and `Bearer ` are trimmed, a key that cannot be written or sent is refused naming the variable, never the value. An existing `.env` needs a typed `yes` (or `--force`) and is kept as `.env.bak-YYYYMMDD-HHMMSS` (never overwriting another backup). The file is written to a `0600` temp file (`O_EXCL`) in the same folder, checked with `check_safe_to_start` on that file alone, then moved with `os.replace`; on failure the old `.env` stays. The template ships in the package and a test keeps it in sync with `.env.example`; the file reads the same for pydantic-settings and `docker --env-file`. Also `--path` and `--allowed-hosts`. Messages never repeat the `--*-key-env` name or the `--path` value; stdin keys are capped at 4 KiB and refused from a terminal; a BOM is dropped; getpass's echoing fallback is refused; the temp file is removed even on Ctrl-C.

- `antifaz doctor` (issue 43, ADR-0017): checks the configuration (the `.env` in `--path` plus `ANTIFAZ_*` variables, with `check_safe_to_start`; names variables, never values; which providers have a key and whether the NER is on), the running gateway (`GET /healthz` with no key, an allowed `Host`, no proxy, no redirects, a timeout; version and NER state) and, only with `--providers`, each provider key by listing its models (free; no redirects; the answer body is never read; proxy settings honoured like the gateway's own client). --timeout is a total deadline per request (not per read); /healthz asks for `Accept-Encoding: identity` and refuses any other encoding, so the 64 KiB cap is real; a `.env` that is not UTF-8 gives a fixed message; a base URL with a user or password is named and its provider is not called; the httpx and httpcore loggers stay at WARNING while it runs. Generic messages only: never a key, a body, an exception or a base URL. Prints next steps (`antifaz verify`, `antifaz setup claude-code`). `✓`/`✗` fall back to `OK`/`FAIL` on consoles that cannot print them (cp1252). Exit codes 0 / 1 / 2. The README quick start runs it with `docker compose exec antifaz antifaz doctor`; the CLI tests on Windows include it. The e2e fake provider answers `GET /v1/models`.
- `antifaz setup claude-code` (issue 31, ADR-0017): points Claude Code at Antifaz by writing only `env.ANTHROPIC_BASE_URL` (and `apiKeyHelper` with `--key-helper`) to the user settings (`$CLAUDE_CONFIG_DIR` or `~/.claude/settings.json`, `%USERPROFILE%\.claude` on Windows) or, with `--project`, `.claude/settings.local.json`; it refuses a repository's shared `.claude/settings.json`. It never reads or writes a key (the Antifaz key goes in `ANTHROPIC_AUTH_TOKEN`; a canary test checks the file, backups, diff and output). Dry run by default: a unified diff in which every value it does not own is hidden, plus the file's SHA-256. `--apply` asks (or `--yes`), checks the SHA-256 again ("changed meanwhile; run again"), keeps a dated backup (`O_EXCL`, `0600`, never over another), writes atomically (temp file in the same folder, `os.replace` with retries on Windows), keeps a BOM and CRLF, 2-space JSON. Invalid JSON, duplicate keys, `NaN`, a non-object top level or `env`, links and files over 1 MiB abort without changes. `--uninstall` removes only entries that still hold the values it would set. Warns about `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` already in the file or shell, a different base URL, plain http to another machine and a managed settings file. Prints next steps (bash/zsh and PowerShell, restart, `antifaz doctor`). Its tests also run in the `cli-windows` job. A real Claude Code run through Antifaz is pending until there is Anthropic credit. `init`'s backup helper is now shared (`write_backup`). Review fixes: backups are a copy of the whole previous file (secrets of other tools included), so for `--project` they go outside the repository (`$CLAUDE_CONFIG_DIR/antifaz-backups/<hash>/`) and never inside a git work tree, and the output gives their full path, says they hold secrets and add up, and that `0600` has no effect on Windows; any user target inside a git work tree is refused (links resolved, case and trailing dots normalised, `.git` files too); lone surrogates, nesting deeper than 64 and `1e999` are refused while reading (in the dry run); previous values of our two entries are never shown, only a short SHA-256; a project `.claude/settings*.json` that sets another `ANTHROPIC_BASE_URL` gives a warning (names only); a linked or junction config folder is explained and written in its real folder; hard-linked files are refused; loopback is decided with `ipaddress`; the key-like check no longer flags long host names or readable names. Second review: key names below the top level (outside `env`) are hidden in the diff as `<hidden key N>`; a permission error while checking the file gives a fixed message; with `--project` inside a repository, a warning if `.claude/settings.local.json` is not git-ignored (`git check-ignore -q`), or that it could not be checked; TECNICO notes that `GIT_DIR`/`core.worktree` setups are not detected and that a killed process can leave a temp file.

### Changed
- Every CI job has a time limit (`timeout-minutes`, 5 to 30; a unit test checks all workflows): "Lint, types and tests" 30, CodeQL 20, supply chain, gitleaks and zizmor 10. A hung step now stops there instead of at GitHub's 6 hours; there is no pytest-timeout.
- Speed tests no longer depend on how busy the machine is; they measure CPU time (`tests/timing.py`). The DoS and scanner tests compare the same work at sizes n and 4n (n calibrates itself, a fresh input per run, best of 3, the ratio must stay below 8, 4n at least the old input size); the fixed-size DoS tests also keep a CPU budget (4 MiB body 15 s, 3,000-turn history 10 s, 5,000 DNIs in `mask()` 2 s, 1 MB guard 1 s, at least 2.4 times the worst cost measured under coverage with every core busy); the 4 MiB body one catches a linear but 10 times slower scanner. In those shape and budget tests the only wall-time limit is a 120 s hang guard, checked when a run returns. The NER pool and time-limit tests check facts (the error, counted log lines, which worker processes are alive, whether a request reached a worker, the deadline each call got) and wait until a replacement worker is ready (`when_ready`); their remaining margins are the deadline plus 3 s, or far below what the fault would take. `antifaz doctor`'s total-deadline test allows 6 s instead of 4 for a 1 s timeout against a 10 s drip. Docs: docs/TECNICO.md, «Cómo se prueba la velocidad».
- `make e2e` now requires Docker Engine 28 or later with Compose v2 (`docker compose`); it was only recommended. `CONTRIBUTING.md` lists the requirements, `make panel-check` included.

### Security

Sessions are bound to the scheme they were made over (`https` or `http-local`): an id moved by hand to the other scheme is refused and the session closed (`scheme_mismatch`). The CSRF token is its own random value, never the session id or derived from it, and only travels in the `<meta>` of the no-store panel page (log canaries check it). A session's last use is refreshed only after every door check passed and only for the panel's own page (`Sec-Fetch-Site` same-origin or none, or no browser): a refused request or a page of another localhost port never keeps it alive. New red-team, property and integration tests (method override included); invariant 12 includes the logout.
- Panel door (issue 53, PR 11b-2a): every `/panel*` answer carries the ADR-0018 headers, except the 400 for a disallowed `Host` and anything answered outside the door; an unexpected error inside the door becomes a fixed 500 JSON with the headers and is raised again for the server log (strict CSP without `unsafe-inline`, `unsafe-eval` or `data:`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `nosniff`, COOP/CORP `same-origin`, a `Permissions-Policy` that turns features off, Bluetooth, HID, serial, WebAuthn and XR included, `Cache-Control: no-store`). Plain HTTP off localhost gets a fixed 403 page and never a cookie. The login needs exactly one `Sec-Fetch-Site: same-origin`, one `Origin` equal to scheme and `Host`, and JSON (else 403, not counted); reads at most 1 KiB within 5 s (a disconnect or a slow body gets the fixed 401 and is not counted, never a 500); checks the 5-failures-a-minute limit before comparing (429 with `Retry-After`, `compare_digest` not called); compares SHA-256 fingerprints with `hmac.compare_digest`; answers every failure with the same bytes; and closes any session it came with (no fixation). Red-team tests cover the other scheme's cookie, case variants, duplicates, path tricks, CSRF variants, fixation, brute force, spoofed `X-Forwarded-*`, oversized bodies and canaries in logs; invariant 12 now covers both doors. AST tests keep the lock-free session store and limiter safe (no `await` in them, every panel route `async def`, and no `await`, `async for` or `async with` in the login after the limiter check). Known limit: behind a trusted proxy that does not add `X-Forwarded-For`, all clients share the login limit.

The gateway refuses to start if the token is empty, short, the example value, not printable ASCII, or equal to `ANTIFAZ_API_KEY` or a provider key (compared with `hmac.compare_digest`), and if `ANTIFAZ_TRUSTED_PROXIES` holds garbage, host bits, a zone id, `0.0.0.0/0` or `::/0`; messages name the variable, never the value. - Review fixes for the panel door pieces (issue 53, PR 11b-1): one shared rule for `ANTIFAZ_TRUSTED_PROXIES` (`antifaz/trusted_networks.py`, used by the settings check and the door), which also refuses IPv4-mapped IPv6 ranges; `doctor` warns (by count) about trusted ranges wider than /24 or /64; the install guides no longer suggest trusting a whole Docker network (the Docker gateway would let any client fake `X-Forwarded-*`) and recommend the exact proxy IP. `X-Forwarded-For` is walked lazily from the right with at most 16 entries and 8 KiB of text, skips empty elements and accepts entries with a port; `Host` ports must be 1-65535. - Anthropic proxy without streaming (issue 5, part b): `POST /v1/messages` and `POST /v1/messages/count_tokens`, with the Antifaz key accepted in `x-api-key` or `Authorization: Bearer` and never forwarded, only `anthropic-version` and `anthropic-beta` forwarded (character-checked), an allowlist of content blocks (`text`, `tool_use`, `tool_result` with text, `thinking`, `redacted_thinking`), reasoning blocks copied untouched in both directions (invariant 9) with a strict key list, still scanned, and their placeholders reserved so a new value never reuses them; attachment keys checked in tool inputs and tools; fixed keys in the `thinking` and `tool_choice` settings; upstream 2xx status kept; lone surrogates rejected with 400; and restore of text blocks and `tool_use.input`. Walk, checks and upstream steps shared with the OpenAI route.
- Configuration is read only from `ANTIFAZ_*` variables (`ANTIFAZ_OPENAI_API_KEY`, `ANTIFAZ_ANTHROPIC_BASE_URL`...), so a shell set up for Claude Code or the SDKs cannot make Antifaz call itself. **Breaking:** rename your `.env` variables.
- OpenAI-compatible proxy without streaming (issue 5, part a): `POST /v1/chat/completions` with the Antifaz key checked in constant time and never forwarded, one `mask()` call over every string of the body (tool-call arguments parsed as JSON), attachments and unmaskable keys blocked, the guard run on the exact bytes sent, provider URL and key only from `.env`, restore of content, refusal and tool-call arguments (always valid JSON), provider errors passed through and fixed messages for timeouts and connection errors. Tests for invariants 2, 4 and 8. ADR-0013 (proposed).
- Egress guard and CLI (issue 4, part b): `guard.check()` blocks with `EgressBlocked` any hidden value found in the final bytes or in decoded JSON strings and keys, with NFKC, format-character, accent and case normalisation; values of 6+ letters and digits are compared without separators or word boundaries, shorter ones with alphanumeric boundaries; it fails closed on invalid UTF-8 and false positives. `antifaz scan` and `antifaz mask` commands that never print values or the table. Property test for invariant 2 without the guard.
- Library `mask()` and `restore()` (issue 4, part a): `[[TYPE_N]]` placeholders numbered by first appearance across texts, escaping of `[[` the user already wrote, single-pass restore of this request's placeholders only, default policy (mask everything but company CIFs), a `Vault` that cannot be printed, copied or pickled, and `DetectorFailed` when the detector breaks. Property tests for invariants 1, 5 and 6. ADR-0012 (proposed).
- Antifaz-Bench (issue 3, part 1): `make bench` measures the detector on the MEDDOCAN test set (downloaded and verified, never redistributed): per-type precision, recall, F1 (overlap and strict), leaks per 100 values including the types not covered yet, and latency. ADR-0011 (accepted) defines how hits and leaks are counted. First results in `docs/benchmark.md`.
- Detector (issue 2, part 2): email (Unicode local part), IPv4, Spanish phone (business and premium-rate numbers excluded; found next to other numbers), payment card (Luhn + known prefix, 7 brands), Spanish, Catalan and Galician style addresses, and with a keyword before them passport, plate, date of birth and the digit-only Portuguese, French and German identifiers.
- ADR-0010 (accepted): a span that contains another one wins, so an email with a DNI inside is masked whole.
- Detector (issue 2, part 1): check-digit validators for DNI, NIE, NIF K/L/M, CIF, NSS, CCC and IBAN, plus Italian codice fiscale and EU VAT via python-stdnum; `scan(text)` returns non-overlapping spans without the value (ADR-0009). Invariant 10: the DNI, NIE, NIF K/L/M, CIF, CCC and Spanish IBAN validators agree with python-stdnum on 5,000 generated cases; the NSS, which stdnum lacks, is checked against documented vectors.
