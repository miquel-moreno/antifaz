## [0.1.0] - 2026-10-02

### Security
- Secret scans never print secrets: `make secrets` scans only the git history with `gitleaks detect --redact`; the pre-commit hook (`gitleaks git --pre-commit --redact --staged`) and gitleaks-action v3.0.0 already redact, now noted in their configs. The Claude Code hook blocks gitleaks scans without full redaction (`--redact` or `--redact=100`), scans of the working tree (`gitleaks dir`, `--no-git`) and `trufflehog filesystem`, with tests; the `code-reviewer`, `privacy-reviewer` and `red-team` agents may never scan the working tree or read `.env`.
- Image vulnerability policy (issue 7, part a): the final stage applies Debian security updates at build time (`apt-get upgrade`, nothing new installed; on 2026-10-01 openssl, libssl3t64 and openssl-provider-legacy 3.5.7-1~deb13u3 and libpcre2-8-0 10.46-1~deb13u3). The Grype gate fails only on high or critical vulnerabilities with a fix (`only-fixed`), with one documented exception in `.github/grype-gate.yaml` (CVE-2026-82049, Python 3.12, fixed only in 3.14); the full report is uploaded as the `grype-report` artifact on every run (kept 30 days), also when the gate fails. 13 high Debian CVEs without a fix remain listed; a distroless image is planned before v0.2.
- Review fixes (issue 29): `anthropic-version` or `anthropic-beta` holding a configured key, also split between the two, gives 400 on every Anthropic route; `GET /v1/models` refuses a key split across query values or in the rebuilt query; provider error bodies are relayed as `application/json` only if they are JSON (otherwise a fixed 502); every response carries `X-Content-Type-Options: nosniff`; 404 and 405 use the error format with fixed messages; invariant 12 classifies routes by (path, method). ADR-0013 and ADR-0015 amendments proposed.
- Invariants 12 and 13 cover the new routes (issue 29): every keyed route must be classified as body proxy (egress guard), query proxy (detector on the query) or local (no provider call), and the canary-key scenarios run on `GET /v1/models` (both providers) and `POST /antifaz/scan`. Red-team tests in `tests/redteam/test_models_and_scan.py`. A repeated `anthropic-version` or `anthropic-beta` header is now refused with 400 on every Anthropic route.
- Hardened CI and supply chain (issue 21): zizmor 1.30.1 (auditor persona) in pre-commit, `make check` and a CI job, with no findings; `permissions: {}` at the top of every workflow and a commented, minimal set per job; per-branch `concurrency` (a new push cancels the previous PR run, never on `main`); Dependabot `cooldown` of 7 days for `uv` and `github-actions`; `CODEOWNERS` with explicit lines for `pyproject.toml`, `uv.lock`, `.github/` and `Dockerfile`; the `python-stdnum<3` upper bound removed (exact versions only in `uv.lock`, no locked version changed).
- Closed-by-default gateway (issue 20, ADR-0015 proposed): one ASGI middleware in front of every route asks for the Antifaz key (`Authorization: Bearer` or `x-api-key`, a repeated key header is refused) on every path except the exact `/healthz`, deciding on the decoded path the router uses; requests with an `Origin` header get 403 unless the exact origin is in `ANTIFAZ_ALLOWED_ORIGINS`, and there is no CORS; requests with a body must be `application/json` (UTF-8) or get 415; `TrustedHostMiddleware` with `ANTIFAZ_ALLOWED_HOSTS`; JSON bodies with repeated keys, also keys that differ only in case or width, get 400; WebSockets are closed; the request log only writes registered route paths; a provider answer that repeats a configured key is dropped with 502. Tests for invariants 12 (every registered route, with HEAD, OPTIONS and aliases, needs the key; every proxy route runs the egress guard) and 13 (canary keys never in logs, error bodies or headers), and attacks in `tests/redteam/test_gateway.py`. Logging setup no longer removes other handlers, so the log checks of invariants 8 and 13 really see the gateway's logs.
- Never-do rules added to the `code-reviewer` and `privacy-reviewer` agents.
- Review fixes (issue 20): the gate refuses to be built with a weak key on its own; `Authorization` and `x-api-key` sent together must both hold the key; attachment keys are matched without case or width (`SOURCE`, `Data` block); a provider answer that repeats a key JSON-escaped (`\u0061`, `\/`) is also dropped with 502, in success and error answers; `Host` is compared without case; `X-Request-ID` is always generated by the gateway.

### Changed
- Overlaps (issue 6, part a; ADR-0016, amends ADR-0010): the loser of a partial overlap is trimmed to the parts nobody else covers instead of being dropped, so no detected letter or digit is left in clear. Pieces without letters or digits are dropped. This can add detections (never remove masked text).
- **Breaking:** a JSON object with the same key twice is refused with 400; keys that only differ in case or width (`content` and `Content`) are refused when the gateway reads that key (one list, `READ_KEYS`), so schemas with `name` and `Name` still pass.
- **Breaking:** the client's `X-Request-ID` is ignored; the gateway always makes its own.
- **Breaking:** stricter startup: provider keys set but empty, not printable ASCII or an example value in any spelling (`change_me`, `ChangeMe`); gateway keys with fewer than 8 different characters; host wildcards broader than `*.example.com`; origins with a path or a trailing slash.
- **Breaking:** Antifaz refuses to start when `ANTIFAZ_API_KEY` is missing, shorter than 32 characters, not printable ASCII or still the `.env.example` value (every example key starts with `change-me`), when a provider key is still the example value, or when `ANTIFAZ_ALLOWED_HOSTS` is empty or `*`. The error names the variable, never the value.
- **Breaking:** `/docs`, `/redoc` and `/openapi.json` are disabled, and a trailing slash is a 404 instead of a redirect.
- **Breaking:** the app is no longer built at import time: run `uvicorn --factory antifaz.api.app:create_app` (as `make dev` does). Behind Docker or a reverse proxy, set `ANTIFAZ_ALLOWED_HOSTS` to the host names clients use.
- The OpenAI route also accepts the Antifaz key in `x-api-key`.
- Red team round 1 (`tests/redteam/`): 11 detector leaks and one crash fixed. The detector now scans a normalised view of the text with a map back to the original offsets (invisible Cf characters dropped, full-width letters and digits folded, odd spaces as spaces, a documented table of Cyrillic and Greek look-alike letters), so masking covers the original characters. DNI, NIE and K/L/M NIF accept single spaces between groups and one line break; IBAN accepts one line break between groups; DNI, NIE, K/L/M NIF and IBAN may touch letters (never digits). JSON bodies nested deeper than 100 levels are blocked with 400 instead of failing with 500. ADR-0014 (proposed).
- Red team review: combining marks, variation selectors, Hangul fillers and a lone CR no longer hide an identifier; long hex runs (hashes) keep the strict boundary (0 false DNIs in 20,000 SHA-1s); a provider response nested too deep gives a fixed 502.

### Added
- Release workflow (issue 7, part c): `.github/workflows/release.yml` runs only on `vX.Y.Z` tags, in the protected `release` environment, with first-party GitHub and Docker actions pinned by SHA and no scanners. It checks that the tag matches `pyproject.toml` and this file, then pushes `ghcr.io/miquel-moreno/antifaz:X.Y.Z` and `:X.Y` (no `latest` while in beta, `linux/amd64` only, no build cache) with the buildx SBOM and full provenance attached, and a SLSA provenance attestation signed with the job's OIDC identity (`gh attestation verify`). No stored tokens. The GitHub Release page is written by hand; PyPI comes with v0.2.
- README in English and Spanish (issue 7, part b): a short summary for non-technical readers on top (problem, demo, what it does, measured results, technologies, role), a **beta** notice saying Antifaz does not guarantee finding all personal data, and below it the quick start (Docker Compose, `.env`, OpenAI and Anthropic SDKs, curl, Claude Code), the detected types (only those with tests), a benchmark summary with the Presidio comparison and the NER precision floor not met, security, what Antifaz is not, known limitations, telemetry and license. Every figure comes from `evals/results/` or from test runs.
- Terminal demo `docs/images/demo.gif` (99 KB), generated by `make demo` (`scripts/demo_gif.py`) from the real output of `antifaz scan`, `antifaz mask` and the official OpenAI SDK through Antifaz against the fake provider of the end-to-end tests, with synthetic data and throwaway keys (your `.env` is never read). Drawn with Pillow, brought only for that run (`uv run --with pillow==12.3.0`), not a project dependency.
- `LICENSE-ASSETS.md`: the code is Apache-2.0; the name "Antifaz" and the logo are © Miquel Moreno Martínez with all rights reserved, except to refer to the project unmodified and, in forks, to say they derive from it. Referenced from both READMEs and `NOTICE`.
- Issue template "I found a leak" (`.github/ISSUE_TEMPLATE/leak.yml`) for values the detector misses, with synthetic data only (required checkbox), type, example, where, version and NER on or off; anything that bypasses fail-closed, the egress guard or restores other users' data goes to a private advisory. The "Missed or wrong detection" template is now "Wrong detection" (false positives and wrong types).
- Telemetry statement in the READMEs, `SECURITY.md` and `docs/TECNICO.md`: Antifaz makes no outbound connections except to the configured providers, has no analytics, and the optional NER runs offline.
- Docker image and Compose (issue 7, part a): multi-stage `Dockerfile` (uv, `uv sync --frozen --no-dev`, no `ner` extra), `python:3.12-slim` and `uv` pinned by digest, fixed non-root user `10001`, nothing written at runtime, no pip, setuptools, wheel or ensurepip, an allowlist `.dockerignore`, and a `HEALTHCHECK` in Python (`python -m antifaz.healthcheck`, no curl in the image, never through an HTTP proxy). `docker-compose.yml` reads the keys from `.env` at start (never in the image), runs read-only with a `/tmp` tmpfs, drops every capability, sets `no-new-privileges` and memory, CPU and process limits, publishes only on `127.0.0.1`; every setting comes from `.env` (no `environment:` override), and `.env.example` allows the service name `antifaz` as host. Image: 259.1 MB on disk, 60.9 MB compressed (14.4 MB of it is the Debian security updates layer).
- `make e2e` (not in `make check`): the real image under Compose with a fake provider that records what it gets, throwaway random keys (your `.env` is never read), and synthetic data. 15 checks: masked for the provider and restored for the client in OpenAI Chat and Anthropic Messages, with and without streaming; healthy, non-root, read-only, no capabilities, loopback-only port; no `.env`, pytest, curl, wget or pip in the image; no values or keys in the logs, also with the DNI in a query string or an unknown path.
- CI job `image`: builds the image, runs `make e2e`, uploads a CycloneDX SBOM (Syft, kept 30 days) and scans the image with Grype. Dependabot also updates the base image digests (7-day cooldown).
- `GET /v1/models` (issue 29): the provider's model list behind the gate. The `anthropic-version` header picks Anthropic, otherwise OpenAI (the same path both SDKs use); 503 if that provider has no key. Query parameters by allowlist only (none for OpenAI; `limit`, `after_id` and `before_id` for Anthropic, each once, with strict values), rebuilt from the checked values and passed through the detector (personal data in a cursor gives 400 `antifaz_blocked`). No other client header is forwarded; a 3xx gives 502 and an answer that repeats a configured key, raw or JSON-escaped, is dropped with 502.
- `POST /antifaz/scan` (issue 29): `{"text": "..."}` in, `{"entities": [{"type", "start", "end"}]}` out, never values or text. Same detector as the proxy (NER included, in the same thread limiter), same JSON rules and size limit; any other field gives 400; a failing detector gives 400 `antifaz_blocked`. New `find_spans()` in `antifaz.mask` (the spans `mask()` works with).
- Static OpenAPI schema in `docs/openapi.json`, generated from the app with `make openapi`; a test fails if it drifts. The gateway still serves no `/docs`, `/redoc` or `/openapi.json`.
- Presidio baseline in Antifaz-Bench (issue 13): `make bench PRESIDIO=1` measures presidio-analyzer 2.2.364 with spaCy 3.8.16 and the MIT model `xx_ent_wiki_sm` 3.8.0, set up for Spanish only with every default recognizer that works in Spanish or any language (it fails at start instead of falling back to English), on MEDDOCAN test with the same metrics, and compares it with Antifaz (without NER, and with NER from the saved results) on the types both cover and MEDDOCAN annotates (EMAIL, PHONE and PERSON) and on leaks over every annotated value; the synthetic set (IBAN, DNI, NIE, card…) goes in a separate table, its bias in favour of Antifaz stated. The new `bench` dependency group is never shipped, not installed in CI, its licenses are checked too, and a test checks that `uv export --no-dev` lists neither Presidio nor spaCy.
- NER infrastructure (issue 6, part a; ADR-0016 proposed), without a model yet: the NER runs in our own pool of `spawn` worker processes (killed and replaced when a call goes past `ANTIFAZ_NER_TIMEOUT_SECONDS`, dies or answers malformed data; the request is blocked with 400), speaking JSON with a size limit and fixed error codes, with the worker's stdout, stderr and logging silenced and Hugging Face offline. Texts are cut into overlapping windows (GLiNER cuts long texts without warning) on the normalised view of ADR-0014. Spans are cached by a BLAKE2b hash keyed with a random per-process secret over the text, model manifest, labels, threshold and chunker version (offsets and types only, bounded LRU). A model manifest with the size and SHA-256 of every file is checked before loading; the shipped one is a placeholder. New `PERSON` type and `NER` layer (lowest priority). `ANTIFAZ_NER_*` settings, off by default: with the NER on and the model missing, mismatched or the backend not installed, Antifaz refuses to start. The real model (GLiNER), its download and the `antifaz[ner]` extra come in part b.
- Real NER model (issue 6, part b): optional `antifaz[ner]` extra (GLiNER `urchade/gliner_multi_pii-v1` pinned by commit, CPU-only torch, transformers, protobuf), `make ner-model` downloads and verifies every file by size and SHA-256, the model loads offline (`weights_only`, strict, local tokenizer), and every window is re-split with the real tokenizer to stay within the model's 384 tokens. The NER reads a view where long blobs (base64, hex, URLs) and digit runs glued to letters are blanked, and too costly calls are refused before running the model without killing the worker. Antifaz-Bench with NER on MEDDOCAN test (threshold 0.6, chosen on dev): leaks per 100 personal values 86.9 → 61.6 overall, names 100 → 2.5; PERSON precision 75 % against any personal data, below the pre-registered 85 % floor, so the NER stays **opt-in and off by default**.
- Every value the NER finds is masked wherever else it appears in the request, with the egress guard's normalisation and boundary rule, so the guard does not block a request because the model saw a name in one message and missed it in another.
- Masking runs in a worker thread (`anyio.to_thread`), so detection never blocks the event loop; `mask()` sends all texts of a request to the detector in one batch.
- Review fixes (issue 6, part a): a NER span never swallows a validator or pattern span (a DNI inside a detected "name" stays a masked DNI even if the policy allows names); the egress guard and the propagation fold the detector's Cyrillic and Greek look-alikes with one shared helper; `ANTIFAZ_NER_TIMEOUT_SECONDS` is one deadline for the whole request (waiting for a worker, every batch and the full reply, with a watchdog) and more than 1,024 windows per request are blocked; a worker that is still loading is kept; a circuit breaker with exponential backoff after 3 failures in a row, logged without text and shown as `ner` in `/healthz`; shutdown never closes a pipe another thread reads; masking uses its own thread limiter; the model directory refuses links, Windows junctions and special files, and every worker checks the model again before loading; only whole NER values of 3+ letters and digits are propagated, at most 200 per request; the span cache is also bounded by its total number of spans. Red-team tests in `tests/redteam/test_ner.py`.

- `antifaz verify` (issue 5, part d, first version): with the current configuration (`ANTIFAZ_*` and `.env`) and without ever calling a provider, runs the gateway in process against a fake provider that records the bytes it gets, plants synthetic DNI, NIE, IBAN, email, phone and card values in every place of both endpoints (system, user text, content parts, tool arguments and results, `tool_use` and `tool_result`, streaming, `count_tokens`) and exits 1 if a value or the Antifaz key reaches the provider, a configured key comes back, a request is blocked or a value is not restored. The report lists entity types and locations only, never values or keys; an unsafe configuration exits 2 naming the variable.
- Contract tests (issue 5, part d): the official `openai` and `anthropic` Python SDKs (dev-only dependencies, not shipped; licenses in `docs/licencias.md`) talk to Antifaz in process, with a fake provider behind it serving hand-written fixtures that mirror the official shapes: chat completions (text, tools, streaming, stream helper), messages (text, `tool_use`, thinking, streaming text, `input_json_delta`, thinking and signature), `count_tokens`, and 401/400/429/502 mapped to the SDK exceptions. Every test checks that no planted value reached the provider and that the SDK got the values back. A sanitisation test scans every fixture for keys, auth headers and personal data and requires a provenance. New `make contract` (also part of `make test` and `make check`).
- Streaming (issue 5, part c): `stream: true` on `/v1/chat/completions` and `/v1/messages` (not on `count_tokens`), with the answer restored on the fly. `StreamRestorer` sends every chunk at once and only holds back a tail (at most 64 characters) that the `restore()` pattern could still read as a placeholder or an escape, so the result does not depend on how the stream is cut (invariant 3, property tests). A small SSE parser of our own (CRLF/LF/CR, multi-line data, comments, unknown fields kept, size limits) and incremental UTF-8 decoding. OpenAI: `content` and `refusal` per choice; tool-call arguments accumulated and sent restored in one delta when the choice finishes; `stream_options` allowlist. Anthropic: `text_delta` per block; `input_json_delta` sent restored as one delta before `content_block_stop` (valid JSON, invariant 4); `thinking_delta` and `signature_delta` byte for byte (invariant 9). Unknown events and fields pass untouched and are counted. Mid-stream failures (timeout, lost connection, malformed SSE, size limits, a key in an event, a stream that ends early) send the safe text and one fixed error event in the provider's format. Every event is checked for configured keys (invariant 13). The provider's stream is closed when the client goes away. Red-team tests in `tests/redteam/test_streaming.py`.
- Streaming review fixes: keys are checked on what the gateway sends after restoring, in streamed and whole answers, decoding up to three layers (a key escaped inside tool arguments is caught), with one tail per field path (choice or block index and field name, unknown fields such as `reasoning_content` included); only text that can still become a placeholder of this request is held back, so wiki links and long `[[...` text no longer stop the stream (the 64-character cap only lets long whitespace go, never errors); a limit hit in one choice keeps the text other choices restored; tool arguments that are a JSON string, array or scalar are parsed and serialized again, and invalid JSON gets each value JSON-escaped; a UTF-8 BOM at the start of a stream is dropped; tool calls without an index pass and are counted; `input_json_delta` is only restored in `tool_use` blocks; a provider error event ends the stream without an extra cut error; chunks with extra top-level fields (`obfuscation`) are never skipped; `anyio` is declared as a direct dependency (MIT).
- Anthropic proxy without streaming (issue 5, part b): `POST /v1/messages` and `POST /v1/messages/count_tokens`, with the Antifaz key accepted in `x-api-key` or `Authorization: Bearer` and never forwarded, only `anthropic-version` and `anthropic-beta` forwarded (character-checked), an allowlist of content blocks (`text`, `tool_use`, `tool_result` with text, `thinking`, `redacted_thinking`), reasoning blocks copied untouched in both directions (invariant 9) with a strict key list, still scanned, and their placeholders reserved so a new value never reuses them; attachment keys checked in tool inputs and tools; fixed keys in the `thinking` and `tool_choice` settings; upstream 2xx status kept; lone surrogates rejected with 400; and restore of text blocks and `tool_use.input`. Walk, checks and upstream steps shared with the OpenAI route.
- Configuration is read only from `ANTIFAZ_*` variables (`ANTIFAZ_OPENAI_API_KEY`, `ANTIFAZ_ANTHROPIC_BASE_URL`...), so a shell set up for Claude Code or the SDKs cannot make Antifaz call itself. **Breaking:** rename your `.env` variables.
- OpenAI-compatible proxy without streaming (issue 5, part a): `POST /v1/chat/completions` with the Antifaz key checked in constant time and never forwarded, one `mask()` call over every string of the body (tool-call arguments parsed as JSON), attachments and unmaskable keys blocked, the guard run on the exact bytes sent, provider URL and key only from `.env`, restore of content, refusal and tool-call arguments (always valid JSON), provider errors passed through and fixed messages for timeouts and connection errors. Tests for invariants 2, 4 and 8. ADR-0013 (proposed).
- Egress guard and CLI (issue 4, part b): `guard.check()` blocks with `EgressBlocked` any hidden value found in the final bytes or in decoded JSON strings and keys, with NFKC, format-character, accent and case normalisation; values of 6+ letters and digits are compared without separators or word boundaries, shorter ones with alphanumeric boundaries; it fails closed on invalid UTF-8 and false positives. `antifaz scan` and `antifaz mask` commands that never print values or the table. Property test for invariant 2 without the guard.
- Library `mask()` and `restore()` (issue 4, part a): `[[TYPE_N]]` placeholders numbered by first appearance across texts, escaping of `[[` the user already wrote, single-pass restore of this request's placeholders only, default policy (mask everything but company CIFs), a `Vault` that cannot be printed, copied or pickled, and `DetectorFailed` when the detector breaks. Property tests for invariants 1, 5 and 6. ADR-0012 (proposed).
- Antifaz-Bench (issue 3, part 1): `make bench` measures the detector on the MEDDOCAN test set (downloaded and verified, never redistributed): per-type precision, recall, F1 (overlap and strict), leaks per 100 values including the types not covered yet, and latency. ADR-0011 (accepted) defines how hits and leaks are counted. First results in `docs/benchmark.md`.
- Detector (issue 2, part 2): email (Unicode local part), IPv4, Spanish phone (business and premium-rate numbers excluded; found next to other numbers), payment card (Luhn + known prefix, 7 brands), Spanish, Catalan and Galician style addresses, and with a keyword before them passport, plate, date of birth and the digit-only Portuguese, French and German identifiers.
- ADR-0010 (accepted): a span that contains another one wins, so an email with a DNI inside is masked whole.
- Detector (issue 2, part 1): check-digit validators for DNI, NIE, NIF K/L/M, CIF, NSS, CCC and IBAN, plus Italian codice fiscale and EU VAT via python-stdnum; `scan(text)` returns non-overlapping spans without the value (ADR-0009). Invariant 10: the DNI, NIE, NIF K/L/M, CIF, CCC and Spanish IBAN validators agree with python-stdnum on 5,000 generated cases; the NSS, which stdnum lacks, is checked against documented vectors.
- Project scaffold with one package per piece of the gateway (detect, policy, vault, mask, guard, providers, restore, audit, web, cli), `GET /healthz` and validation errors that never echo the request body.
- Architecture decision records 0001-0008 (accepted), threat model, `SECURITY.md`, contributing guide and code of conduct.
- CI: ruff, mypy --strict, tests with coverage (90 % required in the privacy pieces), gitleaks, `uv audit`, license check and CodeQL, with actions pinned by commit SHA. Dependabot for dependencies and actions.
- Claude Code kit in `.claude/` (agents, hooks and permissions), with tests for the hooks. The shell hook also watches PowerShell and blocks any mention of `.env` files, `.env` wildcards, `core.hooksPath`, `SKIP=` and force pushes with `git -C`.
