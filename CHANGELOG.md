## [Unreleased]

### Added
- Virtual keys, part 2a: the PostgreSQL base (issue 121, PR 8b-1, ADR-0021 proposed and a dated note in ADR-0020); PostgreSQL stays optional and the gateway does not use it yet. New dependency asyncpg 0.32.0 (Apache-2.0), loaded only by the new `antifaz db` command (a clean-interpreter test and a static import check keep the library, the settings, the gateway, the panel and the rest of the CLI free of it). Separate settings, never a DSN: `ANTIFAZ_DATABASE_HOST` (unset: off), `_PORT`, `_NAME`, `_USER`, `_PASSWORD`, `_SSLMODE` (`verify-full` by default, or `disable`) and `_TIMEOUT_SECONDS`, and `check_database_settings()`, whose messages name the variable, never the value; the settings now hide inputs in their validation errors. New `antifaz/db/`: a typed adapter over asyncpg that passes every connection parameter explicitly (never `PG*` variables or `~/.pgpass`), a timeout on every call, session timeouts, `application_name=antifaz` and `log_parameter_max_length_on_error=0`, and turns every failure into a closed reason with a fixed text (`unreachable`, `timeout`, `auth_failed`, `tls_failed`, `too_old`, `not_utf8`, `not_migrated`, `behind`, `ahead`, `migration_changed`, `other`) without asyncpg's message, raised outside the `except` with the traceback frames cleared; own forward-only migrations (`src/antifaz/db/migrations/NNNN_name.sql` in the wheel, SHA-256 per file, advisory lock, one transaction per file); migration 0001, the `virtual_keys` table with the pepper-version column, CHECKs mirroring the Python rules where SQL can, and triggers that refuse deletes, truncates and changes to a key's number, hash, pepper version, creation or revocation. `antifaz db migrate` and `antifaz db status` (exit codes 0/1/2 like doctor); `antifaz doctor` says whether PostgreSQL is configured without connecting. Common caps of both key stores: limits up to 2 147 483 647 and pepper versions up to 32 767. CI's `quality` job runs the new PostgreSQL tests (`--postgres`, `TEST_POSTGRES_*`) against a `postgres:16` service pinned by digest on 127.0.0.1 with scram-sha-256, and the coverage gate adds `db` (90 %); `make test-postgres` runs the same image locally in Docker, and a plain `make test` skips them and the `db` gate. After review: `connect()` checks the settings itself before calling asyncpg; `antifaz doctor` and `antifaz db` warn «PostgreSQL: TLS off (ANTIFAZ_DATABASE_SSLMODE=disable)» for a host that is not loopback; the applied versions are read with `LIMIT` (known files + 1). Documented limits: `log_parameter_max_length_on_error=0` does not hide the `DETAIL` line of a failing CHECK or UNIQUE (it writes the row), so admins should set `log_error_verbosity = terse` (superuser); a second concurrent `migrate` waits at most `ANTIFAZ_DATABASE_TIMEOUT_SECONDS` and then stops with `timeout`, the same value bounds each migration; the role must own the database or have CREATE in its schema; table names follow the role's `search_path`; the table owner can disable the triggers, `DROP TABLE` fires none and name, scopes, expiry and limits stay editable; `SSL_CERT_FILE` and `SSL_CERT_DIR` widen the CAs `verify-full` trusts.
- Virtual keys, part 1: the library (issue 121, PR 8a, ADR-0020 proposed); nothing uses it yet (no route, CLI, setting or database). New `antifaz/keys/` (standard library only): keys are `afz_` + 43 random base62 characters + a 6-character base62 CRC32 checksum, a typo filter that is not security, and `parse_key()` refuses anything malformed before any lookup; a store keeps only HMAC-SHA256 with a versioned pepper (`PepperRing`, 32 bytes or more, never in a repr, not picklable); closed `KeyRecord`s (fixed number, name, scopes per route group, UTC times, 90-day default expiry, stored per-minute and per-day limits) that are revoked, never deleted; and an async `KeyStore` protocol with `MemoryKeyStore` (create shows the key once, get, list, revoke, verify; async because the PostgreSQL store will use asyncpg behind the ASGI door), whose `verify()` reads the clock first, refuses a revoked key whatever the clock says and never raises and answers a `Caller` (number and scopes only) or a closed reason (`malformed`, `unknown`, `revoked`, `expired`). Key names are a label only (keys are identified by their number): 1 to 64 printable characters with no control or invisible character (categories Cc, Cf, Zl, Zp, Cs, Co, Cn, every Default_Ignorable_Code_Point of Unicode 15.0.0, U+2800). The clear key and the hash are not dataclass fields, so `dataclasses.asdict`/`replace` and pydantic cannot reach them, and neither the key, a rejected name nor a hash stays in the frames of a call that fails half-way. `keys` joins the 90 % coverage gate.

Browser tests in Chromium, Firefox and WebKit with the in-process fake provider, and 40 more reference captures.

- The engine of the panel's «En directo» view (issue 53, PR 11e-1, ADR-0018 and its note of 2026-10-20 for 11e-1); the screen comes in 11e-2. `antifaz/live.py` (standard library, never imports `antifaz.web`): a `LiveFeed` interface (`record`, `snapshot`, `subscribe`), `MemoryLiveFeed` when the panel is on and `NullLiveFeed` (keeps nothing) when it is off. Each event holds only enums, integers and a time rounded down to the minute: origin (`openai_chat`, `anthropic_messages`, `count_tokens`, `scan`, `try`), client (a closed list of User-Agent prefixes; the User-Agent itself is never kept), outcome (`masked`, `no_data`, `blocked`, `upstream_error`), block reason, provider and the distinct hidden values per type (new `Vault.type_counts()`; allowed types such as `ES_CIF` never count). Owner condition: memory only, never a log line or a file (static and red-team tests). Recorded in one place (`api/live_record.py`, an ASGI middleware inside the gate), once per request when it ends, from the notes the routes and error handlers leave; a failing counter never reaches the proxy (only the error's type is logged). New `GET /panel/api/live` (SSE): a live session through the door, `Accept: text/event-stream` (else 406 `not_acceptable`), only `GET`; 200 `text/event-stream` with the door's headers, `no-store` and `X-Accel-Buffering: no`; `snapshot` on connect, `request` per event, `end` (`logout`, `expired`, `replaced`, `busy`, `max_age`, `shutdown`) and close; never a `retry:` field; a closed schema (`web/live_response.py`) whose every JSON leaf is an enum value or an integer. Watching is never a use of the session (`door.NOT_A_USE`, only this route). At most 5 streams per process and 2 per session (else `end: busy`), each until the earliest of 30 minutes and the session's own time left (re-checked then: «Seguir» extends it), cut at once on logout; a queue of 32 per stream (full: a fresh snapshot); a heartbeat comment every 25 s only while a stream is open, and no task or timer when none is; a cut, stalled, cancelled or broken stream never holds a place, and each send has a 30 s deadline (a client that stops reading is dropped; the request-id middleware is now plain ASGI so the deadline really drops the connection); every stream is told on shutdown when the lifespan runs first (under uvicorn, open streams are cancelled after the graceful wait). - The API of the panel's «Prueba un texto» (issue 53, PR 11d-a, ADR-0018 and its note of 2026-10-19 for 11d-a); the page comes in 11d-b. `POST /panel/api/try` (`async def`): session and CSRF token (the door), `GET`/`HEAD` 405, the door's headers and `no-store`. The rate limit comes first, before the body is read or anything awaits: 30 tries in any 60 s per session fingerprint (`web/try_limit.py`, lock-free, bounded, an entry dropped when its session closes), else 429 `too_many_tries` with `Retry-After`. Then the body: at most 128 KiB, declared or streamed (413 `text_too_large`), within 5 s (408 `body_timeout`), never parsed as a form; exactly `{"text": str, "lang": a loaded language}` (repeated or extra keys, NaN, lone surrogates, wrong types: 400 `invalid_try_body`, never quoting the input); a text of at most 20 480 UTF-8 bytes (413). The pipeline is the proxy's own (`web/try_text.py`): `mask()` with the gateway's detector (the NER too) and policy, the egress guard on the masked text, a simulated reply built only from the emitted marker tokens (fixed phrases in Spanish and English, at most 10 markers named) and `restore()`. No AI is called and the module cannot reach a provider: its import closure holds no `antifaz.providers`, `antifaz.api`, `httpx`, `socket` or `ssl`, and an integration test with a provider transport that raises sees zero calls. The proxy goes first: one Try at a time with no queue (another one is 503 `try_busy`, `Retry-After: 1`), taken before the proxy's mask limiter (the panel holds at most one masking thread); with the NER on, each Try gets `NerDetector.for_try()`: the same model and workers without the proxy's span cache (a shared cache would let a Try tell from timing that a text went through the proxy, evict its entries and leave a digest behind), at most 2 windows, one per batch, under a 5 s deadline (a longer text is 413 `text_too_long_for_ner` before any worker is asked), a worker only if no proxy request is waiting for one and an idle, loaded worker exists, checked again before every batch (`NerPool.try_predict`, else 503 `ner_busy`), no effect on the NER circuit breaker, and a 60 s Try-only cooldown after a Try breaks a worker. A proxy request that arrives during a Try waits for one Try batch (one window) at most; with one worker a zero wait would mean killing the batch and reloading the model. «Busy» answers reveal activity, never its content. A failing detector answers `blocked`/`detector_failed`, a value the guard still sees `blocked`/`egress_guard` (200, nothing sent); any other error is a fixed 500 logged with the error's type only. The answer has a closed schema (`web/try_response.py`: strict, extra fields forbidden, input hidden in validation errors): outcome, entities with **UTF-16 offsets** (JavaScript's unit; converted on the server) and `length_utf16`, what the provider would receive (`sent`), the restored simulated reply (`reply`, with each value), counts per type, policy version and NER state; never the original text and no timing. The route has no `response_model`: the answer is validated once, in the route. Logging in again starts a fresh Try budget (the entry goes with the closed session). Values come back only in this answer (the scoped exception to invariant 15): never in logs, counters, «Estado», pages, another session's answer or error bodies, and nothing is written to disk. `MaskResult` gains `found_spans` (start, end, type, hidden or allowed, marker token; never the value; out of the repr), read only by `mask/` and the Try module, `antifaz.policy.VERSION_PATTERN` becomes the one rule for a policy version (`Policy` refuses anything else), and `antifaz.restore` gains `placeholder_parts()`. Tests: unit and Hypothesis (offsets with emoji, ZWJ, flags, combining marks, CRLF, RTL and bidi controls; the simulated reply carries nothing but markers; segments; body parser; limiter; schema), the NER Try path with real worker processes (busy without waiting, a hanging Try never counts toward the breaker), integration (door, body, limit, NER, guard, zero provider calls, no cache use, 503s) and red team (sentinel DNI everywhere, XSS, forged markers, cross-site `text/plain` and `no-cors`, a Try flood does not starve the proxy, with the NER on too, and a hanging Try never trips the breaker).

### Security
- Invariant 13 now covers fragments of a configured key, not only the whole value (issue 76). A provider 401 or 403 is answered with the same status and a fixed `upstream_auth_failed` body on every route that calls a provider (chat, messages, `count_tokens`, `/v1/models`), streamed or not: the provider's body, which may quote the key's prefix and last four characters (`sk-proj-****...abcd`), never reaches the client, and only the status is logged (`antifaz.upstream`). Any other answer (error or success, whole or streamed) holding a recognisable fragment is dropped like a whole key (fixed 502 or the stream's fixed error event): 10 consecutive characters of the key's secret part (without its generic prefix such as `sk-`, `sk-proj-` or `sk-ant-api03-`, which never counts) or, for provider keys only (`sk-`...), the masked shape with 4 to 9 characters of the secret part visible at either end (the hex Antifaz key and admin token have no masked shape: 4 hex characters such as `2025` are only 16 bits) (`****...abcd`, `AbCd****`; markdown bold such as `**abcd**` does not count). Plain string search, no regular expression, fast enough for every streamed event: a set of runs probed every 5 characters, about 2 times the whole-key check instead of about 12 (`api/key_fragments.py`; a test bounds the CPU-time ratio). The fixed message says the provider refused the gateway's credentials or account access (HTTP 401/403) and points to the key and its permissions. Errors that do not mention the key pass as before. `SECURITY.md` moves this case from out of scope to in scope; TECNICO, ADR-0015 (amendment) and the threat model describe it. - Panel CSRF and sessions (issue 53, PR 11b-2b): the door checks the three CSRF layers in one place for every method but `GET` and `HEAD`, closed by default: `Sec-Fetch-Site`, `Origin` and JSON first (403 before the session is looked up, so another origin never refreshes it), then a live session of the request's scheme (401), then exactly one `X-Antifaz-CSRF` equal to the session's token (`hmac.compare_digest`, else the same 403); `SameSite=Strict` is the first layer. - Presidio baseline in Antifaz-Bench (issue 13): `make bench PRESIDIO=1` measures presidio-analyzer 2.2.364 with spaCy 3.8.16 and the MIT model `xx_ent_wiki_sm` 3.8.0, set up for Spanish only with every default recognizer that works in Spanish or any language (it fails at start instead of falling back to English), on MEDDOCAN test with the same metrics, and compares it with Antifaz (without NER, and with NER from the saved results) on the types both cover and MEDDOCAN annotates (EMAIL, PHONE and PERSON) and on leaks over every annotated value; the synthetic set (IBAN, DNI, NIE, card…) goes in a separate table, its bias in favour of Antifaz stated. The new `bench` dependency group is never shipped, not installed in CI, its licenses are checked too, and a test checks that `uv export --no-dev` lists neither Presidio nor spaCy.
- NER infrastructure (issue 6, part a; ADR-0016 proposed), without a model yet: the NER runs in our own pool of `spawn` worker processes (killed and replaced when a call goes past `ANTIFAZ_NER_TIMEOUT_SECONDS`, dies or answers malformed data; the request is blocked with 400), speaking JSON with a size limit and fixed error codes, with the worker's stdout, stderr and logging silenced and Hugging Face offline. Texts are cut into overlapping windows (GLiNER cuts long texts without warning) on the normalised view of ADR-0014. Spans are cached by a BLAKE2b hash keyed with a random per-process secret over the text, model manifest, labels, threshold and chunker version (offsets and types only, bounded LRU). A model manifest with the size and SHA-256 of every file is checked before loading; the shipped one is a placeholder. New `PERSON` type and `NER` layer (lowest priority). `ANTIFAZ_NER_*` settings, off by default: with the NER on and the model missing, mismatched or the backend not installed, Antifaz refuses to start. The real model (GLiNER), its download and the `antifaz[ner]` extra come in part b.
- Real NER model (issue 6, part b): optional `antifaz[ner]` extra (GLiNER `urchade/gliner_multi_pii-v1` pinned by commit, CPU-only torch, transformers, protobuf), `make ner-model` downloads and verifies every file by size and SHA-256, the model loads offline (`weights_only`, strict, local tokenizer), and every window is re-split with the real tokenizer to stay within the model's 384 tokens. The NER reads a view where long blobs (base64, hex, URLs) and digit runs glued to letters are blanked, and too costly calls are refused before running the model without killing the worker. Antifaz-Bench with NER on MEDDOCAN test (threshold 0.6, chosen on dev): leaks per 100 personal values 86.9 → 61.6 overall, names 100 → 2.5; PERSON precision 75 % against any personal data, below the pre-registered 85 % floor, so the NER stays **opt-in and off by default**.
- Every value the NER finds is masked wherever else it appears in the request, with the egress guard's normalisation and boundary rule, so the guard does not block a request because the model saw a name in one message and missed it in another.
- Masking runs in a worker thread (`anyio.to_thread`), so detection never blocks the event loop; `mask()` sends all texts of a request to the detector in one batch.
- Review fixes (issue 6, part a): a NER span never swallows a validator or pattern span (a DNI inside a detected "name" stays a masked DNI even if the policy allows names); the egress guard and the propagation fold the detector's Cyrillic and Greek look-alikes with one shared helper; `ANTIFAZ_NER_TIMEOUT_SECONDS` is one deadline for the whole request (waiting for a worker, every batch and the full reply, with a watchdog) and more than 1,024 windows per request are blocked; a worker that is still loading is kept; a circuit breaker with exponential backoff after 3 failures in a row, logged without text and shown as `ner` in `/healthz`; shutdown never closes a pipe another thread reads; masking uses its own thread limiter; the model directory refuses links, Windows junctions and special files, and every worker checks the model again before loading; only whole NER values of 3+ letters and digits are propagated, at most 200 per request; the span cache is also bounded by its total number of spans. Red-team tests in `tests/redteam/test_ner.py`.

- `antifaz verify` (issue 5, part d, first version): with the current configuration (`ANTIFAZ_*` and `.env`) and without ever calling a provider, runs the gateway in process against a fake provider that records the bytes it gets, plants synthetic DNI, NIE, IBAN, email, phone and card values in every place of both endpoints (system, user text, content parts, tool arguments and results, `tool_use` and `tool_result`, streaming, `count_tokens`) and exits 1 if a value or the Antifaz key reaches the provider, a configured key comes back, a request is blocked or a value is not restored. The report lists entity types and locations only, never values or keys; an unsafe configuration exits 2 naming the variable.
- Contract tests (issue 5, part d): the official `openai` and `anthropic` Python SDKs (dev-only dependencies, not shipped; licenses in `docs/licencias.md`) talk to Antifaz in process, with a fake provider behind it serving hand-written fixtures that mirror the official shapes: chat completions (text, tools, streaming, stream helper), messages (text, `tool_use`, thinking, streaming text, `input_json_delta`, thinking and signature), `count_tokens`, and 401/400/429/502 mapped to the SDK exceptions. Every test checks that no planted value reached the provider and that the SDK got the values back. A sanitisation test scans every fixture for keys, auth headers and personal data and requires a provenance. New `make contract` (also part of `make test` and `make check`).
- Streaming (issue 5, part c): `stream: true` on `/v1/chat/completions` and `/v1/messages` (not on `count_tokens`), with the answer restored on the fly. `StreamRestorer` sends every chunk at once and only holds back a tail (at most 64 characters) that the `restore()` pattern could still read as a placeholder or an escape, so the result does not depend on how the stream is cut (invariant 3, property tests). A small SSE parser of our own (CRLF/LF/CR, multi-line data, comments, unknown fields kept, size limits) and incremental UTF-8 decoding. OpenAI: `content` and `refusal` per choice; tool-call arguments accumulated and sent restored in one delta when the choice finishes; `stream_options` allowlist. Anthropic: `text_delta` per block; `input_json_delta` sent restored as one delta before `content_block_stop` (valid JSON, invariant 4); `thinking_delta` and `signature_delta` byte for byte (invariant 9). Unknown events and fields pass untouched and are counted. Mid-stream failures (timeout, lost connection, malformed SSE, size limits, a key in an event, a stream that ends early) send the safe text and one fixed error event in the provider's format. Every event is checked for configured keys (invariant 13). The provider's stream is closed when the client goes away. Red-team tests in `tests/redteam/test_streaming.py`.
- Streaming review fixes: keys are checked on what the gateway sends after restoring, in streamed and whole answers, decoding up to three layers (a key escaped inside tool arguments is caught), with one tail per field path (choice or block index and field name, unknown fields such as `reasoning_content` included); only text that can still become a placeholder of this request is held back, so wiki links and long `[[...` text no longer stop the stream (the 64-character cap only lets long whitespace go, never errors); a limit hit in one choice keeps the text other choices restored; tool arguments that are a JSON string, array or scalar are parsed and serialized again, and invalid JSON gets each value JSON-escaped; a UTF-8 BOM at the start of a stream is dropped; tool calls without an index pass and are counted; `input_json_delta` is only restored in `tool_use` blocks; a provider error event ends the stream without an extra cut error; chunks with extra top-level fields (`obfuscation`) are never skipped; `anyio` is declared as a direct dependency (MIT).
- Anthropic proxy without streaming (issue 5, part b): `POST /v1/messages` and `POST /v1/messages/count_tokens`, with the Antifaz key accepted in `x-api-key` or `Authorization: Bearer` and never forwarded, only `anthropic-version` and `anthropic-beta` forwarded (character-checked), an allowlist of content blocks (`text`, `tool_use`, `tool_result` with text, `thinking`, `redacted_thinking`), reasoning blocks copied untouched in both directions (invariant 9) with a strict key list, still scanned, and their placeholders reserved so a new value never reuses them; attachment keys checked in tool inputs and tools; fixed keys in the `thinking` and `tool_choice` settings; upstream 2xx status kept; lone surrogates rejected with 400; and restore of text blocks and `tool_use.input`. Walk, checks and upstream steps shared with the OpenAI route.
- Configuration is read only from `ANTIFAZ_*` variables (`ANTIFAZ_OPENAI_API_KEY`, `ANTIFAZ_ANTHROPIC_BASE_URL`...), so a shell set up for Claude Code or the SDKs cannot make Antifaz call itself. **Breaking:** rename your `.env` variables.
- OpenAI-compatible proxy without streaming (issue 5, part a): `POST /v1/chat/completions` with the Antifaz key checked in constant time and never forwarded, one `mask()` call over every string of the body (tool-call arguments parsed as JSON), attachments and unmaskable keys blocked, the guard run on the exact bytes sent, provider URL and key only from `.env`, restore of content, refusal and tool-call arguments (always valid JSON), provider errors passed through and fixed messages for timeouts and connection errors. Tests for invariants 2, 4 and 8. ADR-0013 (proposed).
- Egress guard and CLI (issue 4, part b): `guard.check()` blocks with `EgressBlocked` any hidden value found in the final bytes or in decoded JSON strings and keys, with NFKC, format-character, accent and case normalisation; values of 6+ letters and digits are compared without separators or word boundaries, shorter ones with alphanumeric boundaries; it fails closed on invalid UTF-8 and false positives. `antifaz scan` and `antifaz mask` commands that never print values or the table. Property test for invariant 2 without the guard.
- Library `mask()` and `restore()` (issue 4, part a): `[[TYPE_N]]` placeholders numbered by first appearance across texts, escaping of `[[` the user already wrote, single-pass restore of this request's placeholders only, default policy (mask everything but company CIFs), a `Vault` that cannot be printed, copied or pickled, and `DetectorFailed` when the detector breaks. Property tests for invariants 1, 5 and 6. ADR-0012 (proposed).
- Antifaz-Bench (issue 3, part 1): `make bench` measures the detector on the MEDDOCAN test set (downloaded and verified, never redistributed): per-type precision, recall, F1 (overlap and strict), leaks per 100 values including the types not covered yet, and latency. ADR-0011 (accepted) defines how hits and leaks are counted. First results in `docs/benchmark.md`.
- Detector (issue 2, part 2): email (Unicode local part), IPv4, Spanish phone (business and premium-rate numbers excluded; found next to other numbers), payment card (Luhn + known prefix, 7 brands), Spanish, Catalan and Galician style addresses, and with a keyword before them passport, plate, date of birth and the digit-only Portuguese, French and German identifiers.
- ADR-0010 (accepted): a span that contains another one wins, so an email with a DNI inside is masked whole.
- Detector (issue 2, part 1): check-digit validators for DNI, NIE, NIF K/L/M, CIF, NSS, CCC and IBAN, plus Italian codice fiscale and EU VAT via python-stdnum; `scan(text)` returns non-overlapping spans without the value (ADR-0009). Invariant 10: the DNI, NIE, NIF K/L/M, CIF, CCC and Spanish IBAN validators agree with python-stdnum on 5,000 generated cases; the NSS, which stdnum lacks, is checked against documented vectors.
